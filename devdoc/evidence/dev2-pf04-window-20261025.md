## 요청과 범위

사용자의 “계획서를 commit하고 시작”, “1단계부터”, “단계별 commit” 지시에 따라 D2 독립 계획 검토를 채택하고 **`82c14ba`로 계획·분석을 먼저 커밋**했다. 이후 P1 도구와 그 연결부만 구현했다. 담당·통합·계약 확인자는 `/root`, 작성자 외 검토자는 `/root/pf04_evidence_review`다. 이 기록을 포함한 P1 변경을 별도 커밋하며 push는 수행하지 않는다.

수정 대상은 platform의 Linux 관측 primitive, 두 engine-worker의 측정 경계, bounded Python runner와 해당 시험이다. 엔진의 snapshot·계수기·WAL·복구 알고리즘은 변경하지 않았다. 기존 네 PF04 campaign FAIL과 DEV2/B2/D0 INCOMPLETE는 유지하며 이 실행은 성능 인수가 아니다. P2–P4는 착수하지 않았다.

## 구현과 관측 해석

- [platform 관측](../../crates/platform/src/performance.rs): calling-thread TID, monotonic timestamp, thread rusage(user/system CPU·minor/major fault·voluntary/involuntary switch), nonblocking Unix 연결 primitive. 기존 nix의 `resource` 기능만 추가했고 신규 crate·외부 의존·unsafe는 없다.
- [공유 private gate](../../crates/testing/engine-worker/src/measurement_window.rs): 환경값 `XADBTEST_WINDOW_SOCKET`과 `XADBTEST_WINDOW_TOKEN`이 모두 설정된 경우에만 활성화한다. 경로·32자리 hex token, 고정 HELLO/START/STOP 순서, 최대512byte line, 교환별 절대2초 deadline을 확인한다. 비활성 경로는 새 timestamp/rusage 관측을 수행하지 않는다.
- [K0 연결](../../crates/testing/engine-worker/src/performance.rs)과 [영속 연결](../../crates/testing/engine-worker/src/durable_performance.rs): 기존 warmup·측정 loop·길이·표본화·원 clock을 유지하고 loop 밖에서 시작·종료를 관측한다. 시작 gate 오류는 output.error에 보존하고 측정에 들어가지 않는다. 종료 gate 오류에서도 첫 제품 오류와 이미 수집한 측정 결과를 보존하며 종료 진단 오류를 stderr에도 남긴다. 구성 오류는 측정에 들어가기 전에 거절한다.
- [runner](../../scripts/dev2_measurement_window.py): 새 결과 디렉터리에 입력·worker hash·source·원 stdout/stderr·PMU raw·경계·오류·정리 결과를 보존한다. OS peer PID=생성 child PID=worker TID와 `/proc` starttime을 대조한다. regular 입력은 최대64KiB+1만 읽어64KiB 초과를 거절하고 stdout4MiB, stderr/perf 각1MiB를 넘으면 실패로 기록한다.
- PMU는 `--tid`, `--no-inherit`, `--no-scale`, disabled start와 FIFO ACK를 사용한다. 준비 단계에서 확인한 권한/지원 부재만 `RUSAGE_ONLY`로 진행한다. 이후 ACK 소실·빈 최종 통계는 실패다. disable ACK 뒤 소유 perf에 SIGINT로 통계 배출·종료를 요청한다. worker zombie의 `/proc` 소멸을 기다리는 교착을 피한다.
- 전체 deadline 기본30초·최대60초, 정리는 소유 process group별 TERM 최대2초→필요 시 KILL 최대2초다. PID는 WNOWAIT로 정리 전까지 예약하여 재사용된 PID에 신호를 보내지 않는다. cooperative SIGINT/SIGTERM과 예외에도 정리하며, 외부 SIGKILL·비협조 종료는 finally를 보장하지 않는다.

worker 경계에는 rusage/clock 비용이, PMU bracket에는 handshake·경계 처리도 포함된다. `boundary_excess_ns`는 worker 경계 길이와 원 loop 길이의 차이이며 인위적으로 빼서 인수값을 만들지 않는다. rusage CPU는 microsecond 정밀도를 ns 단위로 표현한다. perf coverage는 반올림된 표시값이므로 `REPORTED_FULL_COVERAGE`도 실제 multiplexing 부재의 증명이 아니다. raw count·missing·coverage만 보존하고 비율·GHz·원 실패 원인 판정을 만들지 않는다. perf ACK에는 sequence ID가 없어 이미 대기 중인 불청객 ACK는 거절하지만 현재 ACK와 구별 불가능한 악의적 지연 응답을 인증하는 프로토콜은 아니다.

진단 output의 path는 원 path 뒤에 `.diagnostic_window.v1`을 붙인다. 기존 인수 checker는 이를 거절한다. 영속 worker의 출력 구조 검증은 정확한 진단 path를 먼저 확인하고 임시 path로 기존 bound 검증을 재사용한 뒤 진단 path를 복구하여 직렬화한다. 기존 protocol·인수 validator는 변경하지 않았다. 독립 정답 adapter 역시 exact identity를 확인한 임시 copy만 정규화하며 원 byte를 덮어쓰지 않는다.
