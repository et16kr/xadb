## Purpose and boundary

Connect the existing actual selected `PageFileReader` to bounded clean buffer frames, frame pins, duplicate-load coordination and clock replacement. This is the first actual buffer consumer under S2. It has no dirty pages, mutation/apply, flush, undo/status transient pin, multi-page reservation or transaction admission. A frame pin only prevents replacement of this buffer slot. It does not prove logical visibility or lifetime of undo/status graph edges. Later dirty-buffer work must extend this same storage owner after its WAL/DWB/reservation contracts; this is not a second product engine.

The reader owns the same exclusive writer-namespace borrow as today. FILEMAP selection, file lengths and physical page reuse are fixed for the whole buffer lifetime. Outstanding external handles must not mutate this namespace; the higher coordinator retains that obligation. There is no coherent cache across unrelated writer contexts. A selected profile is required; no caller-invented memory limit or namespace supplies it.

## F02 API, ownership and errors

Private `storage/read_buffer.rs` and `read_buffer_tests.rs`. Existing `page_io.rs` supplies `profile()` and a shared side-effect-free `validate_page_request(profile,identity,kind,level)` helper; `read_page` calls the same helper without changing errors. Root owns module, native test façade, runner, fixtures, build plan and owner contract registration.

`ReadFrame::new()` constructs zero payload plus private frame header. A frame has `RwLock<[u8;16384]>` payload and `Mutex<Header>` metadata. Header holds Empty/Loading/Clean, full expected request, u64 frame generation, u32 pin count and one referenced bit. No public metadata setters. Every frame's payload and metadata are distinct from every other frame by ordinary Rust slice ownership.

`ReadBuffer::new(reader: PageFileReader<'source,W>, frames: &'memory mut [ReadFrame], load_scratch: &'memory mut [u8;16384]) -> Result<ReadBuffer<...>,BufferError>` consumes the reader and exclusively borrows caller frames/scratch. The exclusive frames borrow prevents two pools sharing frames. After construction the pool internally shares the frames immutably through locks. No heap allocation occurs in constructor, pin, read, release or replacement. Caller allocates/reserves the workspace before acquiring buffer use. No Arc is allocated per pin.

N must be1..=profile.buffer_bytes()/16384 (256/1024/4096). This isolated reader consumes at most that profile's whole frame budget; it cannot run beside another buffer over the same context. It does not allocate foreground/rollback/flush reservations. Frame overhead is <=256 bytes/frame (size assertion), pool overhead <=4096 bytes. Payload N*16384 plus one loading page16KiB; the existing reader owns root16KiB+scratch16KiB. Metadata overhead <=N*256+4096, <=1,052,672 bytes at4096; load/root/scratch48KiB are workspace, not extra replacement frames. Actual OS/runtime/RSS and future opcode F05 remain unclaimed.

Constructor checks capacity before consuming any frame state. It clears unpinned old state for a later sequential reuse of the caller workspace, retains each generation, and rejects poisoned locks, orphaned Loading claims and nonzero pin counts without repairing them. No old pin can outlive the previous pool by Rust borrow rules. Failure may modify caller scratch/metadata but no DB bytes. Reusing memory after panic/poison does not clear poison.

`buffer.pin(expected: PageIdentity, kind: PageKind, level:u8) -> Result<PagePin<'pool,...>,BufferError>` may perform actual synchronous read on a miss. It never waits for a frame to become unpinned or for an already Loading same page. `PagePin` is neither Clone nor Copy and owns one count. `pin.read() -> Result<PageReadGuard<'pin>,BufferError>` acquires only shared content access; `PageReadGuard::view()` borrows its payload as validated `PageView`. The guard lifetime is tied to the pin, so pin release cannot happen before content access ends. Views cannot escape the guard. Decode-on-view may revalidate the envelope; cell semantics remain the downstream decoder's job. Frame index/generation are private except test inspection. Drop releases one count without panic or I/O. A caller must release partial pin sets before waiting/retrying for a multi-page operation; this leaf supplies no wait loop.

Errors: `Read(PageIoError)` preserves lower errors, `InvalidCapacity`, `BufferBusy`, `IdentityMismatch`, `PinLimit`, `GenerationExhausted`, `Poisoned`. All are non-DB-mutating. Source logical/read errors free the failed Loading reservation, consume its generation, and permit explicit later retry. Panic/poison fences the entire instance; later operations return Poisoned. A Drop seeing mismatched identity/generation/count also fences without panicking. This is not a panic recovery path.

## Lookup, load and replacement

Pool has a short clock/selection mutex and a separate loader mutex owning the reader+one load_scratch. No file read, checksum, allocation or content-lock acquisition runs while the selection mutex is held. Frame headers are short leaf locks under the selection lock; pin Drop/publish may take a frame header alone. Nothing holding a frame header requests selection/loader/content locks. Content reads never request selection. Loader mutex can serialize source reads but must not serialize existing cached hits.

Request validation order: fenced/poisoned state, existing `PageFileReader` request validation (namespace, kind/level, allocation-page-position), then bounded lookup. Physical lookup key is DB/FileId/page_no, not owner/incarnation. A cached/loading physical key with different expected incarnation/owner/owner-generation/kind/level returns IdentityMismatch before loading or count changes. Selected source is fixed; a fresh pool is required for a new physical reuse generation. Exact Loading returns BufferBusy immediately. Exact Clean uses checked pin increment and sets referenced=true, returning the existing generation without I/O. PinLimit changes no state.

No matching key: scan at most2N clock candidates, beginning at hand and advancing moduloN once per visit. Empty is eligible; Loading and pinned Clean are skipped. Unpinned Clean with reference=true is cleared and skipped; unreferenced Clean is eligible. Eligible generationMAX cannot be incremented and is skipped. On first available candidate, checked generation+1, request, Loading, pins0 and reference=false are installed before releasing selection. At most one Loading exists per physical key. No eligible candidate => GenerationExhausted if a generation-exhausted eligible slot was seen, otherwise BufferBusy. This decision never loops unboundedly; clock/ref bits may change on Busy.

Loader gate then reads through the actual PageFileReader into the one load_scratch. Source I/O and checksum happen without selection/frame-header/content locks. Success copies the full validated image under the claimed frame's exclusive content lock after I/O ends, releases content/loader, then publishes matching Loading generation to Clean with pins1/referenced=true. The original requester receives that pin. Until publication all competing requests see Loading. Failure publishes Empty with pins0 and unchanged consumed generation. The old victim image is never exposed after claim, even if load fails. It need not preserve an evicted clean cache entry; source DB bytes are intact.

A RAII Loading reservation must clean up/fence on unwind so that panic cannot strand an apparently healthy Loading pool. On ordinary read error the instance stays reusable; on poison or unexpected state mismatch it is fenced. Loader poisoning, header poisoning and content poisoning all lead to Poisoned and no mutation APIs.

## Resource and compile verification

The no-allocation claim is narrowed to the buffer module's own constructor/pin/read/release/clock code, whose only persistent state is borrowed caller frames/scratch and fixed scalar locks. It does not claim the supplied port, test adapter, OS I/O or error construction never allocates. No global unsafe allocator hook is introduced. Test2 checks exact workspace sizes and every frame budget boundary; source review checks no Vec/Box/Arc allocation/growing map in buffer module. Runtime total allocator/RSS remains unmeasured and is not an F05 completion. This replaces r0's allocator event counter requirement before any implementation/execution.

Borrow lifetime verification uses three compile-fail cases plus matched positive baselines, compiled against the actual private module in temporary source exports. A new narrow Python runner appends a private `buffer_borrow_probe` module to each export's lib.rs, runs cargo check --lib --locked --offline, and records the exact Rust JSON diagnostic code and probe span. It must first compile the unmodified baseline. Negative cases require E0505(pool moved while pin later used), E0505(pin moved while read guard later used), E0499(second mutable frames borrow while first pool later used). Matched positive ordering variants must compile. Privacy/import errors, missing dependencies, a general build failure or a successful negative case cannot pass. Product source and its fingerprint stay unchanged; every probe export/diff/log is retained separately. Runner self-tests reject missing/duplicate/wrong-code/wrong-span compiler diagnostics. It is a lifetime compilation check, separate from ten runtime unit tests.

## Cached hit must not take the loader lock

At construction, before moving PageFileReader into the loader mutex, copy its completely decoded `Profile` and selected generation into immutable scalar pool fields. The shared pure helper is a module-level `page_io::validate_page_request(profile: Profile, expected: PageIdentity, kind: PageKind, level:u8) -> Result<(),PageIoError>`; it accesses no reader, mutex, file or mutable state. Both PageFileReader::read_page and ReadBuffer::pin call it with their own validated Profile copy. Buffer preflight, cached hit, Loading rejection, pin release and pin.read never lock the loader mutex or ask the reader for profile. Only a claimed miss accesses the reader/loader gate. This corrects any ambiguous reader-method preflight in r0.

The paused B read test must get A hit+full read+release and exact B Busy before releasing the read barrier. It explicitly detects an accidental loader lock in the hit/preflight path.

## Short critical sections and fencing

Global selection mutex holds only clock hand and coordination. It visits frame headers one at a time. Drop and load completion take one frame header without selection. No code holding a frame header requests selection/loader/content. No content guard is acquired under selection. I/O reads and checksum execute with only the exclusive loader gate, using the one preallocated load page. Full image copy under the claimed content write lock occurs after I/O; before metadata publication the copy lock and loader are released. Loading is not an exposed read state.

A loader reservation guard is created immediately after claim and before attempting loader lock. On unwind it sets an atomic fenced flag; it does not recover mutex poison or try another I/O. On an ordinary lower read error it explicitly transitions its matching Loading generation to Empty, then disarms. On success it publishes matching Clean/pins1/referenced=true, then disarms. Unexpected mismatch or poisoned header/content/loader/selection sets fenced and returns Poisoned. A pin Drop encountering poison/mismatch sets fence without panic; only a valid matching Clean header has its positive pin count decremented. Locks poisoned by the panic keep their poison after constructor failure or pool teardown.

Fenced flag uses Acquire loads/Release stores. An operation already granted before a concurrent fence may finish its read-only access; new calls observing the fence cannot acquire a new pin/read. This is not a mechanism for recovering and continuing a poisoned engine. Frame generation changes only on claimed load, never on pin acquire/drop; zero is never assigned as a usable generation and u64MAX never wraps.

Callers do not invoke a miss-capable pin while holding content/page latches or while waiting with a partial mutation pin set; higher operations must reserve all frames or release/retry. This read-only leaf itself never owns a content latch during I/O and adds no blocking wait for a pin to become available.


Shared use across scoped threads relies solely on Rust auto traits: the concrete supplied writer W and its associated W::File must be Send so the loader Mutex can be Sync. The type may still be used on one thread with a non-Send port. No unsafe impl Send/Sync, interior pointer aliasing or unsafe buffer access is added. Unit/native concurrency evidence identifies the concrete port used and does not certify arbitrary external port implementations.

The pool overhead <=4096-byte assertion covers its own scalar/control/loader fields when instantiated with the supported Linux writer/file and the fixed fake test writer/file. Both concrete size_of values are checked in their corresponding unit/native test assembly; it is not a bound on every possible generic W or W::File. Caller frame overhead is checked as size_of(ReadFrame)-16384 <=256. Profile maximum4096 therefore bounds frame overhead at1,048,576 bytes. The concrete pool overhead adds at most4096. Loader output/root/control scratch are three distinct16KiB workspaces(49,152 bytes), separately charged outside replacement payload. Underlying OS/runtime allocations, externally supplied port-owned memory, full metadata/system quota integration and RSS remain outside this leaf's proved scope. A generic external port cannot claim that these fixed concrete-port size assertions bound its own hidden allocations.

Future dirty/transaction integration must reserve the same frame payload once and separately charge this metadata and workspace in the existing global owners. It may not start a second buffer alongside this exclusive selected reader or count this isolated capacity check as full F05 admission/rollback/recovery proof.

## 최초 저장 세션의 후속 D2 계약

후속 [최초 저장 세션](dev3-storage-session.md)은 reader/WAL과 공유하는 영구 fence를 추가하고 cached hit·read/view·healthy Loading claim 취소·조건부 pin Drop의 경합을 구체화한다. 원래 standalone 읽기 buffer 결과를 shared 구현의 실행 증거로 재사용하지 않는다. D2 채택이며 구현/실행 NOT_RUN이다.
